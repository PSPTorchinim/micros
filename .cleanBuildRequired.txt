IMPORTANT: After downgrading Swashbuckle from 10.1.0 to 6.9.0, a clean rebuild is required.

To resolve the TypeLoadException for AddHeaderParameter.Apply method:
  System.TypeLoadException: Method 'Apply' in type 'Shared.Services.Security.AddHeaderParameter' 
  from assembly 'Shared, Version=1.0.0.0' does not have an implementation.

The error occurs because cached assemblies from Swashbuckle 10.1.0 are incompatible with 6.9.0.

## For Local Development:

1. Clear NuGet cache:
   dotnet nuget locals all --clear

2. Clean all build artifacts:
   rm -rf Services/*/bin Services/*/obj

3. Restore packages:
   dotnet restore

4. Rebuild:
   dotnet build

## For Docker Deployments (TrueNAS/Docker Compose):

The Dockerfile already includes proper restore steps, but Docker layer caching may cause issues.

**Option 1 - Rebuild without cache (RECOMMENDED):**
   cd Docker
   docker-compose -f dj-panel-composer.yml build --no-cache
   docker-compose -f dj-panel-composer.yml up -d

**Option 2 - Force rebuild specific service:**
   cd Docker
   docker-compose -f dj-panel-composer.yml build --no-cache <service-name>
   docker-compose -f dj-panel-composer.yml up -d <service-name>

**Option 3 - Nuclear option (removes all images and volumes):**
   cd Docker
   docker-compose -f dj-panel-composer.yml down -v
   docker system prune -af
   docker-compose -f dj-panel-composer.yml build --no-cache
   docker-compose -f dj-panel-composer.yml up -d

**Verification:**
   # Check that containers are running
   docker-compose -f dj-panel-composer.yml ps
   
   # Check logs for the error
   docker-compose -f dj-panel-composer.yml logs <service-name>

**Note:** The --no-cache flag ensures Docker doesn't use cached layers that may contain 
the old Swashbuckle 10.1.0 assemblies. This forces a fresh download of all NuGet packages
including the correct Swashbuckle 6.9.0 and OpenApi 1.6.22 versions.
